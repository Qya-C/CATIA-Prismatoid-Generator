### 新增校验（均在进入 CATIA 之前完成）

重合顶点、自交边对、凸性、侧面共面性、体积交叉校核
（散度定理网格体积 vs 拟柱体公式 `h/6·(S₁ + 4M + S₂)`）。
比值偏离 1 即说明几何有问题。

### 界面（本次调整）

**A. 移除"扭转角"，斜置只保留"顶面错位"。**

理由（几何上必然）：顶面相对底面做独立扭转（β ≠ 0）时，侧棱增量
`D_{i+1} − D_i` 不再与底边 `e_i` 平行，侧面失去共面性、变成**双曲抛物面**，
无法封闭为实体，只能输出曲面。

而"顶面中心在截面平面内错开 `(pu, pv)`"已经完整覆盖斜置这一需求，
且 `D_{i+1} − D_i = (k−1)·e_i` 恒与底边平行，**侧面永远是平面梯形，永远可以出实体**。

因此扭转是既多余、又会破坏实体的自由度，已从界面移除：

- 删除"扭转角 β"输入框
- 删除"允许曲面侧面"开关（没有扭转就不可能非共面，此开关失去意义）
- `ObliquePanel` 改名"斜置（顶面错位）"，只留 `pu / pv` + 只读倾斜角
- `_on_ok` 固定传 `twist_deg=0.0`、`allow_nonplanar=False`

内核对外的 `twist_deg` 形参**保留**（默认 0.0，数学上完整，既有调用不会报错），
但文档已写明它不在界面暴露。内核自检中"扭转"相关用例也保留，
作为"非共面必然被检出"的回归测试。

**B. 修复"部分控件够不着"（严重，本次自己引入又修掉）。**

上一版为了省空间，把**顶点表**和**输出类型 / 生成方式**放进了 `QTabWidget`。
Qt 会把非当前页的控件**同时置为 disabled 且 hidden**，于是用户根本改不了：

```
轮廓·顶点表   !!DISABLED!!            QPlainTextEdit < QStackedWidget < QTabWidget
输出类型      !!NOT-VISIBLE-TO-DLG!!  QComboBox < QStackedWidget < QTabWidget
```

修复：

- 彻底移除 `QTabWidget`，改为纯 `QWidget` 列布局
- "输出"（输出类型 / 生成方式）直接并入「尺寸 / 输出」组，永远可见
- "顶点表"改为内联块，仅在轮廓模式为「顶点表」时 `setVisible(True)`
- "尺寸驱动"、校验明细用默认折叠的折叠块承载（**折叠只是收起，不是禁用**）
- 「斜置」改为**默认展开**：它是 2.0 的主打功能，默认折叠会让人以为没有

> 设计教训（已写入 README）：**为了省空间，只能把控件放进"默认展开的折叠块"，
> 或让它按需出现；绝不能藏进标签页。**

另修：`_set_visible` 无法接收紧凑模式下的裸容器控件（会 `TypeError`）。

**C. 修复"控件落在窗口之外、点不到"（几何实测定位）。**

B 改完之后仍有控件点不到。这次不靠猜，直接量控件在窗口里的**几何位置**，
一次就看清了：

```
对话框窗口高 330      左列滚动区视口高 288
左列内容真实高 604
轮廓·类型     底部=335  > 窗口高 330   ← 落在窗口外
轮廓·边数 n   底部=362  > 窗口高 330   ← 落在窗口外
斜置·错位 pu  底部=565  > 窗口高 330   ← 落在窗口外
```

根因是**窗口高度策略错了**：我此前用
`QVBoxLayout.setSizeConstraint(SetMinimumSize)` 让对话框按"最小尺寸"打开，
而最小尺寸来自控件外框的 `minimumSizeHint`，只有 209 ——
于是窗口永远很矮，内容溢出到窗口之外，下半部分控件根本点不到。

修复：

- 新增 `_content_height()`：**向滚动区内部控件问高度**。
  `QScrollArea` 自身的 `sizeHint` 不反映内容，必须问 `area.widget()`。
- 新增 `_sync_dialog_size()`：把窗口高度调到刚好装下内容（受屏幕比例封顶），
  装不下时才由滚动区滚动。屏幕封顶比例从 0.72 提到 0.78。
- 左列滚动条的纵向策略设为 **AlwaysOn**："能滚动"必须是确定的，不能靠用户去找。
- 滚动区视口加宽 320 → 380（内部控件最小宽约 362，视口更窄会把右侧裁掉）。
- 紧凑模式改用短标签（`标准面` / `原点+法向` / `三点确定`、
  `顶点表 XY` / `顶点表 极坐标`），全称放在 tooltip 里；
  过长的中文项会把内层控件撑宽，导致它自己的文字显示不全。
- 内容变化后重算窗口高度：切换"顶点表"轮廓模式、展开/收起折叠块时都会调用。

实测结果：窗口 330 → **624**，左列内容 604 全部装下，
此前够不着的三个控件全部 `OK`，且滚动条始终可用作为兜底。

**D. 布局教训：最小尺寸 ≠ 合适尺寸。**

C 的教训是：**布局的"最小尺寸"不等于"合适尺寸"。**
一个参数面板的 `minimumSizeHint` 永远很小（边框 + 一个字段），
若用它当窗口尺寸，内容必然溢出。窗口尺寸应当由内容高度决定。

**E. 改为可自由缩放的布局，并把控件宽度还给用户（本次重构）。**

用户反馈（附截图）："控件完全点不动，鼠标点上去没任何反应"、
"控件很小、点不中"、"上下箭头和参数部分重合"。
这三句指向同一个根因：**我把参数列锁死在 380px，并把旋转框压到
70~92px** —— 上下箭头因此盖住数字，很多控件窄到无法命中。

同时用户要求"主窗口可自由缩放、各分组跟着缩放，类似 Excel"。

重构内容：

- 用 `QSplitter` 分左右两栏（参数 / 只读派生量），**可拖动分隔条**调整比例，
  窗口放大时两侧一起变宽
- 去掉参数列的固定宽度上限；对话框最小尺寸 660×420，可自由拉大
- 旋转框宽度 70/92 → **96/112**，X/Y/Z 三格 → 96
- 新增 `enforce_min_widths()`：给每个控件设**硬下限**
  （下拉框 124、旋转框 100）。QFormLayout 在空间不足时会压缩控件列
  （实测下拉框被压到 54px），设了硬下限后布局无处可压，只能把窗口撑宽
- 新增 `unify_label_columns()`：把各组的标签列统一到同一宽度，
  所有控件从同一列开始，不再错落
- 表单改为 `DontWrapRows` + `ExpandingFieldsGrow`

**F. 表单对齐：混用两套对齐方式是错位的根源。**

渲染截图暴露了另一处观感问题：各行标签与控件**纵向错位**，
看起来像控件叠在一起。根因是我自定义的 `_hrow()` 把"标签 + 控件"
塞进**控件列**，而其它行用 `form.addRow(标签, 控件)` 走**表单标签列** ——
同一张表单里混用两套起点，相差一个标签列宽，行高也被撑开。

修复：不再混用。一律用表单原生标签列；多值行（X/Y/Z）
改用 `_row_items()` 容器承载，落在控件列内，与单值行对齐。

> 方法论教训：**界面问题必须渲染出来看。** 我前两轮只检查
> "控件是否 enabled / 是否 visible"，两次都判定"正常"，
> 而实际是"被压碎 + 错位"——这些只有把窗口渲染成图才能发现。

### 脚本与构建（本次加固）

脚本层修掉四个真实故障，全部已在 README 的
「四个已经踩过的 `.bat` 陷阱」一节中记录，避免后续重犯：

1. **中文导致批处理解析崩坏。** `cmd.exe` 按代码页（GBK/936）按字节读取 `.bat`，
   UTF-8 中文会把同行命令字符一起吃掉（`echo`→`cho`、`if`→`f`）。
   → **规定：`.bat` 只允许 ASCII，注释用英文**；中文只写在 `.md` 里。

2. **`where python` 会匹配路径片段。** 构建目录含 `...CATIA Python 工作目录...` 时，
   `where` 会返回被截断的无效路径，而只排除 `WindowsApps` 拦不住。
   → 候选解释器**必须真的跑通 `import sys`** 才被采用。

3. **`for /f` 不能嵌在 `if (...)` 括号块内。** 会让 cmd 解析器错位，
   报出极具误导性的 `Edit was unexpected at this time.`
   → 改用 `goto` 标签 + `call` 子程序。

4. **`py` 启动器不能被引号包住。** `"py" -3 -c ...` 会失败并报
   `Unable to create process using '...\Python311\py" -c ...'`。
   由于多数机器都走 `py -3` 这条路径，旧脚本必然失败。
   → 用 `PYLAUNCH` 标志区分"启动器"与"真实 exe 路径"两种调用形态。

构建流程改进：

- 拆分为 `build.bat`（打包 + 自动冒烟测试）与 `build_once.bat`（仅打包）。
  旧脚本让 PyInstaller 对 onefile 做了**两遍完整分析**，白等约 90 秒。
- 冒烟测试不再用 `timeout`：它在 stdin 被重定向时会报错并挂住脚本，
  改用 `ping` 提供延迟。
- 冒烟测试的判定修正：`rthook_log.py` **每次正常启动也会写一行 banner**，
  所以"日志存在"不等于崩溃，改为检测真正的 `Traceback` / `Error`。

### 本版修正的缺陷

0. **界面占据半个屏幕（本次修复）。**
   旧版把基准面／轮廓／尺寸／斜置四组控件全部纵向堆叠，并硬编码
   `setMinimumHeight(760)`；基准面的原点、法向、三个点各占独立一行
   （最多 12 行），顶点表又固定占 150px。Qt 的最小尺寸由"控件外框"决定，
   于是窗口最小高度被顶到 640，无法缩小。
   修复：
   - 基准面的原点／法向／三点改为"一行三格"，最多 12 行 → 4 行
   - 顶点表移入独立标签页，只在选「顶点表」时出现
   - 两个对话框改为「左参数（可滚动）／右只读派生量」两栏
   - 斜置、校验明细、输出等高级项默认折叠
   - 不再硬编码最小高度；窗口最大尺寸封顶在屏幕可用区域的 72%
   实测：多边形对话框 600×640 → **533×330**；圆形 600×402 → **533×330**；
   最小尺寸由 600×640 降到 **274×217**（不再被内容顶死）。

1. **k=0 多边形棱锥无法生成实体（本次修复）。**
   圆形路线 `_gsd_circle` 通过 `plan_cone(k)` 把 `k=0` 替换为
   `CONE_TOP_EPS_REL`，得到"极小但真实"的顶面；多边形路线 `_gsd_polygon`
   却把 `k` 直接透传，`k=0` 时顶面所有顶点重合为一点，`_closed_wire`
   无法建立顶面边，报 `更新失败于『创建顶面边』`。
   自检中的 `回归·六棱锥 k=0` 与 `★斜棱锥（offset, k=0）` 两例因此失败。
   修复：多边形路线同样经 `plan_cone()` 处理，与圆形路线完全对齐；
   另加一条诊断信息说明 0.1% 的极小顶面近似。
   修复前 20/22，修复后 **22/22**。

2. **`diagnose_v2.py` 基线数字过期（本次修复）。**
   `EXPECTED_PASS_COUNT` 仍是 1.0 时代的 `20`，而 2.0 内核的用例表为 22 条
   （新增 `★斜棱锥` 与 `★拒绝·非共面却要实体`）。
   过期基线导致真正的用例失败被"与基线不符"这句含糊提示掩盖。
   修复：改名为 `BASELINE_PASS_COUNT = 22`，并把判定拆成两条独立检查
   —— 用例总数是否改变、是否有用例失败 —— 使这类事故不再沉默。

3. **圆的轴线（v1 隐患，2.0 已修）。**
   轴线必须沿平面法向 `N`，不能用"底面中心 → 顶面中心"；
   `offset ≠ 0` 时后者会倾斜，导致圆不落在预期的截面平面上。

### 已知限制（沿用并重申）

1. **点不能作为放样截面。** `add_section_to_loft(点, 1, 空)` 不报错，
   但随后 Update 必失败。故 `k=0` 的锥体/棱锥一律用极小顶面近似：
   顶面尺寸 = `CONE_TOP_EPS_REL × R`（默认 `1e-3`，R=50 时约 0.05mm），
   体积相对误差约 0.1%，肉眼不可见。
   探查函数 `probe_point_section()` 持续监测；若将来支持，可切
   `CONE_MODE="point"`。**圆与多边形两条路线现均如此处理。**

2. **Part Design 的 Pad 不可用。** `add_new_pad` / `add_new_pad_from_ref`
   对 `k=1` 的纯圆柱也返回 `E_FAIL`；且 pycatia 的 `Pad/Prism` 继承链上
   未暴露拔模角接口。故 Part Design 路线停用。

3. **派生量按理想 k 计算。** `k=0` 时界面显示的体积是精确的数学真值，
   而实际几何体积比它大约 0.1%（因顶面是极小截面而非真正的点）。
   这是有意为之：**请勿"修正"。**

4. **扭转/独立顶面轮廓/各向异性缩放会破坏侧面共面性**（数学必然，不是 bug）。
   此时只能输出曲面，无法封闭为实体。程序会检出并报告非共面面号，
   要求实体时明确拒绝而不是硬做，避免产出外观正常但几何错误的东西。

5. **凹轮廓配合大 offset 可能出现侧面互相穿插。** 体积交叉校核会报警
   （实测 `扭转 20°` 用例比值 0.92635），需目视复核。

### 工程约束（开发时务必遵守）

- 空的 Loft / Fill 一旦入树，会让整文档 Update 失败 → **先配置、后入树**
- 对 COM 对象调用 `dir()` 会抛 `E_FAIL` → 必须用 `_public_names()` 包裹
- 一个特征失败后该文档进入错误状态，后续 Update 全部连带失败
  → **自检必须每个用例用全新文档**
- 存在多份代码副本的风险 → 用 `version_info()` + 同目录检查识别
- `k=0` 的近似逻辑**两条路线必须同源**（都走 `plan_cone()`），
  否则会出现"圆锥能画、棱锥画不出来"这类只影响一类图形的缺陷

### 遗留的人工复核项

- 多边形对话框 → 轮廓「正 n 边形」、n=6、R=50、h=80、k=1、offset 全 0

## [1.0.0] — 2026-09-20 · 首个冻结版本

支持生成六种参数化图形，底面为**正 n 边形**或**圆**：

| 缩放比 k | 棱边体 | 回转体 |
|---|---|---|
| `k = 0` | n 棱锥 | 圆锥 |
| `0 < k < 1` | n 棱台 | 圆台 |
| `k = 1` | n 棱柱 | 圆柱 |
| `k > 1` | 倒台（上大下小） | 倒台 |

### 输入参数

| 参数 | 说明 |
|---|---|
| 基准面 | XY / YZ / ZX 三个坐标平面 |
| 基准点 | 底面中心坐标 (x, y, z) |
| 边数 n | ≥ 3 的整数；**拓扑参数，创建后不可改** |
| 驱动量 | 外接圆半径 R / 边长 a / 内切圆半径 r_in，**三选一**，互相换算 |
| 垂直高 h | 两平行截面平面的垂直间距（**不是轴长**） |
| 缩放比 k | 顶面对底面的位似比；`k=0` 自动识别为锥体 |
| 输出类型 | 实体 / 曲面 |
| 生成方式 | 自动（GSD）/ GSD / Part Design（本机不可用） |

### 派生量（只读显示）

底面积、顶面积、体积、侧棱长、半锥角、锥顶距底面距离、拔模角。

体积公式（只用到垂直高 h）：

```
V = h/3 · (S₁ + S₂ + √(S₁·S₂))      其中 S₂ = k²·S₁
k=1 → V = S₁·h        k=0 → V = S₁·h/3
```

### 几何内核

统一仿射映射，六种图形共用同一条代码路径：

```
Q_i = C₀ + h·N + k·(P_i − C₀)
```

固定约定：缩放中心 = 基准点 C₀；顶面沿用底面平面基；轮廓绕向统一逆时针。

### 已验证基线

主能力自检 **11/11 通过**（每个用例在全新空 Part 中隔离执行）：

- 3 项底层能力：点与直线、圆（轴线在前签名）、Fill（add_bound）
- 7 项六种图形实体：六棱柱、六棱台、六棱锥、三棱台、圆柱、圆台、圆锥
